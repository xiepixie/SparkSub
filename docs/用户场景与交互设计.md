# 用户场景与交互设计

## 一、产品定位

视频字幕助手不只是“导出字幕”工具，而是在观看、定位、理解和整理视频内容之间建立一条连续工作流。

双界面不是重复功能，而是分别承担两种注意力模式：

- **播放器旁滚动面板**：低操作、强同步，服务于“我正在看”。
- **浏览器侧边栏**：高信息密度、强检索，服务于“我要查、找、跳、复制、学习、追踪和管理任务”。Side Panel 只有一层主导航：`字幕 / 学习 / 复习 / 追踪 / 转录`。追踪与转录是一级工作区，不再以覆盖式抽屉形成“侧边栏中的侧边栏”；设置是唯一允许临时展开的全局偏好面板。

## 二、核心场景

### 1. 普通观看

用户打开视频后不进行额外操作。插件自动识别视频、等待播放器就绪、选择上次使用的语言，然后在播放器旁显示字幕列表。

当前句保持在视图中部，上下文仍然可见。用户不需要在视频画面、YouTube 原生字幕和另一个窗口之间反复切换视线。

### 2. 密集学习

用户需要反复查找概念、代码名或术语。此时打开侧边栏，在完整字幕中搜索，点击匹配句直接跳转视频时间点。

搜索结果不改变原始字幕数据，清空搜索词后立即恢复完整列表。

### 3. 手动阅读上下文

用户向上滚动查看前文时，插件必须暂停自动跟随，否则下一个播放事件会将用户强行拉回当前句。

面板会明确显示“恢复跟随”，由用户决定何时回到实时字幕。点击任意字幕跳转后，自动跟随恢复。

### 4. 多语言和自动字幕

轨道选择器同时显示语言和字幕类型。用户切换轨道后，播放器旁面板和侧边栏必须同时切换，不出现两个界面使用不同语言的状态。

最后一次选择的语言会成为后续视频的首选；找不到同语言时，再按“人工中文 → 自动中文 → 人工其他语言 → 第一轨道”降级。

### 5. 站内连续切换视频

YouTube 和哔哩哔都会在不完整刷新网页的情况下切换视频。插件通过媒体标识而非普通 DOM 变化判定是否切换，并取消旧视频请求，防止旧字幕覆盖新页面。

### 6. 全屏与剧院模式

普通模式下，滚动面板优先放在视频页右侧区域。进入全屏后，面板进入全屏容器右上角；退出全屏后自动回到页面侧栏。

面板可收起，收起状态在后续视频中保留，避免打断娱乐性观看。

### 7. 获取失败和自动恢复

界面不以“有轨道”作为成功标志，只有字幕正文成功解析并提交后才进入就绪状态。

YouTube 请求按以下顺序降级：

1. 重放浏览器原生字幕请求。
2. 请求播放器实时轨道地址的多种格式。
3. 请求播放器重新开启目标轨道并捕获新请求。
4. 读取 YouTube 自带的转录面板。
5. 首次失败时延迟自动重试一次。

诊断信息只记录阶段、HTTP 状态、正文长度和解析条数，不记录完整字幕网址或会话令牌。

### 8. 自动队列与“离线转录当前视频”必须是两种意图

从推荐页、追踪页或批量入口加入普通后台任务时，用户可以关闭视频标签页。该路径保持 **caption-first**：优先使用与任务媒体身份一致的平台字幕；YouTube 页面链路不可用时，由 SparkScribe bundled helper 使用受验证的 `yt-dlp` 读取人工字幕、自动 CC 与翻译字幕；确认没有可用平台字幕后，才进入本机 ASR。

用户在当前播放页明确点击“离线转录当前视频”时则是 **local-asr**：这不是“再试一次自动字幕发现”，而是要求 SparkScribe 重新听当前视频。因此该路径必须绕过打开标签页的现成 cues、平台 caption tracks 和恢复出来的 caption cache。Bilibili 在入队时锁定当前 `BVID + CID`，执行前再通过权威 view metadata 证明同一分 P 的 CID；只有身份成立后才请求 DASH 音轨。YouTube 则锁定 `videoId + mediaKey`。两种平台的 v2 Native request/result 都保留媒体身份相关性，晚到或跨媒体结果不得提交。

队列语言仍属于任务语义，但浏览器不选择具体模型。SparkSub 只读取 `sparkscribe.browser-native/2` 的 `localASR.languages` 与 `supportsAutoLanguage`；Qwen、Parakeet 或未来其他模型的选择、缓存和生命周期由 SparkScribe 管理。平台没有用户所需字幕且 SparkScribe capability 不支持所选语言时，显示明确限制，不静默改用另一种语言。

队列卡片只区分用户真正需要理解的来源：平台字幕或 SparkScribe 本机转录；具体 engine 只作为可选诊断标签，不参与路由。失败卡片显示稳定错误码、脱敏处理建议和可重试性；签名 URL、Cookie、Authorization、HTML 或原生异常原文不得持久化到界面状态。

### 9. 本机能力不完整

转录工作区展示的是 **能力** 而不是一排具体模型安装状态：本机 ASR 是否可用、支持哪些语言、YouTube captions/media 是否可用、Bilibili remote media 是否可用。模型和 `yt-dlp` 的安装、校验与删除由 SparkScribe 的 Models & Runtime 管理；SparkSub 不复制第二套模型管理器。

Native Messaging host 按需连接而非常驻 daemon。长任务通过进度和 execution lease 维持扩展端状态；用户取消、真正静默超时、浏览器关闭或 host EOF 都会终止对应 job 并清理 SparkScribe browser workspace。恢复任务必须重新证明媒体身份，不复用过期 Bilibili 签名 URL、无 owner caption artifact 或上一视频的页面状态。

## 三、全场景功能覆盖矩阵

当前功能分支覆盖以下生产力场景；Swift/CoreML 与真实媒体链路仍以 macOS CI 和实机门禁为准：

### 1. 基础播放与伴随阅读
- YouTube 与哔哩哔哩全场景（包含单视频、分P、合集、番剧及特别聚合活动页）字幕高精度解析。
- 播放器旁 Shadow DOM 伴随滚动面板，支持多行换行、字号微调与点击跳播。
- 侧边栏搜索、实时高亮、双向时间轴同步。

### 2. 合集与多分P批量收割 (Batch Harvest)
- 自动探测 B 站分P列表、电视剧/番剧季、UP 主自选合集与系列专栏。
- 多并发批量抓取，支持选择性逐 P 勾选，并按目录序号而不是网络完成先后组织最终结果。
- 选好视频后再决定去向：**复制全文**会把所选字幕合成纯文本直接进入剪贴板；**合并长文件**可下载单一 Markdown / TXT；需要保留逐集文件时再选择 **ZIP**，其中可用 SRT / Markdown / TXT。时间戳开关只在文本型输出中出现，避免把“选择内容”和“选择文件容器”混成一个操作。
- 播放器旁面板与独立 Side Panel 共用同一套批量输出语义，并通过共享 Batch Export Module 生成复制文本、合并文件与 ZIP；两个界面只负责最终剪贴板/下载投递。Side Panel 打开批量弹窗时只接受规范化后的字符串媒体 ID，不能把 DOM 点击事件对象误当作 BV 号传给视频信息接口。
- 平台目录进入批量 UI 前必须先规范化标题：若 B站 `part` 已自带 `P1/P2…` 前缀，不得再次拼接成 `P1 P1`；输出层只追加稳定的合集序号，不再猜测或二次修正文案。
- YouTube 批量抓取与 B站保持相同的字幕偏好语义：`人工优先 / 仅人工 / AI优先` 必须真实影响轨道选择；用户取消任务时，应立即取消正在运行的 Native Host 字幕请求，而不是等待当前视频完成。
- 支持提取官方 DASH 纯音频流直链。

### 3. AI 图文报告与多模态学习工作台 (AI Visual Course Workbench)
- **一级 Workspace 不变，内部只按学习意图分任务**：外层继续保持 `字幕 / 学习 / 复习 / 追踪 / 转录` 五个一级工作区；本轮只收敛学习与复习内部。学习页提供 `图文讲义 / 关键要点 / 概念深解`，复习页提供 `核心速览 / 自测翻卡 / 易错排查`。`currentWorkspace` 仍是一级真值，mode 只表达当前页内部选择，不能反向改变一级导航。
- **视觉层级跟随真实学习路径**：先选择要得到的产物，再选择执行方式：`内置 AI 直接生成 / 交给外部 AI`；生成后的截帧、复制、导出才是辅助动作。只有图文讲义展示截帧与视觉证据托盘，其他纯文本任务不暴露画面规划工具。窄侧栏隐藏任务副标签，只保留任务名，避免六类任务因为说明文字挤压而难扫读。
- **复习页落实逐题 Recall 保护**：`deep_qa` 要求模型输出可配对的 `Qn / An` 三级标题。界面优先把每道题的答案变成独立“查看第 N 题答案”折叠卡，让用户逐题作答、逐题核对；外部 AI 若返回了可识别答案区但没有稳定配对结构，则降级为整段答案折叠；若连答案边界都无法识别，再明确提示本次无法自动保护。Markdown 原文与导出始终保持完整。
- **最终笔记是连续文档，不是卡片里的卡片**：生成或导入完成后，Markdown 直接流入学习/复习工作区，不再额外套结果容器与正文边框。正文作为可收缩的 flex 文档占满可用宽度；表格、代码和长公式只在各自局部容器横向滚动，不能把整个 Side Panel 撑宽。标题、粗体、引用、列表、代码与段落必须输出合法块级 DOM，不能依赖浏览器替非法 `<li>` / `<p>` 结构兜底修正。承载知识的引用、低级标题、表格和公式不能靠降低文字对比来制造层级；层级优先用字号、字重、间距、背景和边线表达，只有真正的元信息才使用 dim 色。
- **阅读内容高于控制 chrome**：学习/复习页的主要停留对象是生成后的笔记，而不是任务按钮。正文使用约 `13.5–15px` 的响应式阅读字号和更充足行高；任务切换、生成/外部 AI、复制/导出等控制保持约 `28–32px` 的紧凑高度与 `10px` 级字号。典型 Side Panel 宽度下隐藏“快速唤醒/主动回忆/边界检查”这类副标签，只保留真正需要决策的任务名；宽窗口再展示辅助说明。品牌区直接使用打包图标资源，不用文字占位符模拟图标。
- **主题按语义 token 适配，不按组件逐个打补丁**：`text / text-body / dim` 分别承担标题强调、长文正文和弱辅助信息；`primary` 是强调色，承载文字时必须配套 `on-primary`，不能假设 B站青、YouTube 红等亮色背景都适合白字。主操作统一消费 `action-primary-*`，成功、警告、失败、处理中状态分别使用状态填充色与状态文字色，浅色主题使用更深的文字色以维持小字号可读性。长文正文优先使用 `text-body`，引用不因“次要样式”而降成难读的弱灰。
- **长内容更新避免重复全量重建**：Markdown 块占位符按类型单次扫描恢复，图片使用 lazy loading + async decoding；同一视频内切换学习/复习任务时复用有界的产物、渲染结果和阅读位置热缓存，纯文本任务最多保留少量 detached DOM，图文讲义不缓存包含 base64 图片的 HTML/DOM，避免用内存换速度过头。高清证据图从 IndexedDB 恢复以及保存时的 Base64→Blob 写入都只允许最多 2 张的小并发/小批量，用户切走学习页时可取消后续图片恢复，不能一次性把整组高清 Blob 与 Base64 同时物化。字幕时间轴/阅读两种视图也按 `mediaKey + trackId + cueRevision` 复用 DOM，只有字幕版本真正变化才失效。外部规划连续截取多张画面时只更新进度，全部取帧和初筛结束后一次提交截图托盘 DOM，不在每新增一张高清 data URL 时重新序列化和解码整份托盘。单张用户操作仍即时更新，保证反馈速度与批处理性能兼得。
- **图文讲义只有两个用户阶段，内部取帧不是第三阶段**：阶段一负责“确定章节骨架 + 找出真正需要画面的时间窗口”，SparkSub 随后按窗口执行寻道、取帧和去重；阶段二直接沿用同一章节骨架写最终笔记并安放画面，不重新切章。界面进度统一表达为 `阶段 1/2 · 规划章节与取帧 → 阶段 2/2 · 组织笔记`，不把播放器执行截图这种内部动作包装成第三个认知任务。
- **阶段一字段各有明确去向，不为“看起来完整”而堆字段**：`chapters.windowStart/windowEnd` 同时负责最终章节时间范围与第二阶段字幕分组，`summary` 只提供全片主线，`samplingWindows.windowStart/windowEnd/targetSec` 只负责播放器找稳定帧，`importance` 用于证据预算，`reason` 用于解释为什么需要取样，`contentHint → expectedSurface` 告诉第二阶段画面类型，`samplingGoal → evidenceGoal` 告诉第二阶段这张图应补充什么，`chapterId` 把截图放回正确章节。复用用户手动截图时不重复寻道，而是把缺失的这些规划语义补到已有截图上。
- **外部 AI 与内置 AI 使用同一两阶段契约**：六种任务都能从主工具栏进入“外部 AI”，但入口本身只展开协作流程，不产生隐式复制。五种纯文本任务仍执行“复制任务 → 外部 AI 完成 → 导入结果”；图文讲义执行“复制阶段一任务 → 导入章节与取样规划 → SparkSub 取帧/投递画面 → 复制阶段二任务 → 导入笔记”。界面只强调当前阶段：阶段一未完成时不同时暴露阶段二操作；规划导入并取帧完成后，阶段一收起为完成状态，阶段二才成为主要操作。若用户重新规划，只清自动规划帧并保留手动截图。导入后的 `summary / chapters / samplingWindows` 会继续传入阶段二，不能只留下截图后再让第二个模型重新规划结构。规划 JSON 和最终 Markdown 使用两个独立导入入口，不靠粘贴内容猜当前步骤。
- **外部 AI 回流必须保留任务身份**：最终 Markdown 以当前 mode 写入独立缓存，不能统一降级成 `course_notes`。因此外部生成的关键要点仍回到关键要点，易错排查仍回到易错排查，自测内容仍继续应用答案保护；同一视频的六种学习/复习产物可以并存，切换任务时独立恢复。
- **AI 配置按“共享连接 + Workspace 模型”理解**：学习和复习不是两套独立账号。Base URL 与 API Key 是底层连接能力，两页共享；学习模型与复习模型可以分别选择。学习页可配置支持图片输入的强模型承担图文讲义，复习页可选择更快或成本更低的文本模型。设置面板同时展示两者并高亮当前页，顶部徽标也显示“学习/复习 · 模型名”，避免两个入口看起来像两份独立配置却互相覆盖。
- **“图文讲义”表达使用意图，不强迫内容套课程模板**：入口保持简洁，但生成结构必须根据视频本身变化；访谈、纪录片、人文、艺术和软件演示不会被硬套成“定理 + 例题”式课程结构。
- **时间信息只为可回到视频的学习行为服务**：阶段一必须读取完整带时间戳字幕来确定章节范围和取样窗口；阶段二若已有有效章节规划，SparkSub 会先按 `windowStart/windowEnd` 把原字幕确定性分到对应章节，再把分组后的时间字幕交给模型，因此模型不必重新判断“哪句话属于哪一章”。最终主要章节使用 `## [01:15–03:30] 标题`，Side Panel 将时间范围渲染为可点击按钮，点击范围跳到该章节起点；只有标题中的明确时间控件负责跳播，标题正文仍可正常选择文字。关键要点、概念深解、核心速览、自测翻卡、易错排查等纯文本任务仍只发送字幕正文，不携带逐句时间。
- **AI 语境以标题与标签为主，而不是把页面元数据全塞给模型**：Bilibili 的标签统一来自 `x/tag/archive/tags`，YouTube 使用 `videoDetails.keywords`，两端都归一进入 `MediaContext.tags`；标题、标签、当前分段与分类用于主题和术语消歧。作者/频道、平台名和长简介仍可供产品 UI 与追踪使用，但不再默认进入学习、复习、翻译和字幕校对 Prompt。开始 AI 处理前会针对当前 `tabId + mediaKey` 按需确认一次最新 `MediaContext`，避免字幕先就绪、标签异步尚未到达时构造出缺标签的任务。
- **提示词读起来像正常编辑任务**：需要定位时字幕使用 `00:12  文本`；ASR 逐句回填使用 `L0001 | 文本`；报告图片使用 `![说明](frame://00:12)`；其余语义任务直接使用纯文本字幕。不再把 `[Language & Output Format]`、`[Task Nature]` 等大量元指令和字幕数据混在同一层。JSON 只保留给程序真正需要解析的规划结果。
- **报告结构随视频类型变化**：数学/理工强调对象、推导、条件和边界；软件教程强调目标、步骤、界面状态、代码/参数和失败场景；人文社科强调事实、观点、论据、背景和不同视角；访谈、演讲、艺术、设计、历史与纪录片使用与内容相匹配的叙事方式。不会为了统一模板把所有视频都写成“定理 + 避坑 + 解题动作”。
- **截图允许宽覆盖，但最终证据要克制**：每个候选窗口先比较最多 3 个低分辨率像素签名，只编码该窗口质量最好的一张高清 WebP。最终证据帧提高到约 `1536px / WebP 0.90`，优先保住小字号 PPT、代码、公式和文献细节；跨窗口使用保留二维空间结构的紧凑 fingerprint 做近重复判断，并检查最近已保留候选而不只比较相邻上一张，减少“同版式但不同文字”误删和 `A → B → A` 重复漏检。自动证据预算随视频时长动态增长；用户手动截图优先保留，不会被自动筛选静默删掉。
- **截图不要求用户守着视频窗口，但必须等到真实媒体帧可读**：阶段一 seek 到目标点后不会仅凭 `currentTime` 或 `seeked` 就截图，而是继续确认播放器已经结束寻道且拥有可读的当前解码帧。网络慢、目标区间尚未缓冲时由媒体层有限重试一次，仍不可用才跳过该窗口并留下可解释诊断；不会把上一帧、黑帧或过期 Canvas 冒充成功。普通切到其他标签页、其他窗口或应用不影响这个契约，截图不以焦点、`requestAnimationFrame` 或页面呈现回调为前提；只有浏览器真正冻结/丢弃了视频页时才属于不可执行状态。
- **存储跟最终报告走，不跟候选数量走**：低分辨率 fingerprint、评分和未入选候选只存在于当前运行内存。内部自动生成时，只有最终筛选后的图片才上传给多模态模型并进入 IndexedDB；保存新版本时先按小批量写独立图片集，再一次提交 Markdown 指针与索引，成功后才清旧图；相同视频的保存串行执行，因此补图、删图或保存失败不会把上一版报告与下一版图片交叉污染。最终图片只额外保存“用户手动/规划生成、重要性、用途”这类轻量语义。
- **配置状态与生成状态一致**：顶部徽标显示已保存模型；输入框有未保存修改时不允许直接生成。服务目录探测只告诉用户协议和可见模型，“测试当前模型”则真实调用输入框中的准确模型，并显示服务实际返回模型、延迟与短响应摘要，测试本身不会保存配置。
- **最小网络权限**：AI Base URL 当前只直连 `http://localhost` / `http://127.0.0.1`。需要云端模型时由用户自己的本地 OpenAI-compatible 网关转发，不为 AI 功能申请全网 host permission。文本模型测试只验证文本调用，不把它宣传成多模态图片能力测试。
- **失败语义可解释**：认证、网络或模型调用失败直接停止生成并显示真实阶段；只有“模型已经返回，但规划 JSON 格式不合格”才允许降级为字幕 + 手动帧继续合成。
- **交互式报告呈现**：主要章节的 `## [开始–结束] 标题` 会渲染成“时间范围按钮 + 标题”，点击时间范围跳到本节起点，让用户从笔记直接回看原视频；普通 H2 不受影响。图片引用继续使用 `frame://` 内部引用，报告里默认完整 `contain` 显示，点击缩略图打开原图预览，右上角 `▶ MM:SS` 单独负责跳到截图真实时间。引用找不到精确秒数时只在约 ±5 秒内匹配真正最近帧；渲染、删除和 ZIP 导出共享同一帧解析规则。旧 `[SCREENSHOT: ...]` 历史讲义继续兼容。AI/外部导入 Markdown 按不可信内容渲染，表格原始 HTML 不会被反转义，图片 URL 也受协议白名单约束。
- **外部 AI 投递不用伪可靠拖拽**：Chrome Side Panel 里的脚本生成 `File` 拖到另一个网页上传框并不能稳定等价于从 Finder 拖文件，因此移除“拖拽全部”。直接投递改成“复制精选拼图”：底层也硬限制最多 4 张，自动按 1～2 张单列、3～4 张双列排版并限制画布尺寸，避免超长图被模型整体缩小。超过 4 张或需要完整原图时使用“原图打包” ZIP；阶段二合成词只引用最后一次真正复制/打包的图片集合，联系表里解码失败而未画进去的图也不会继续出现在提示词里。
- **切视频不会串内容，误导入也能纠正**：学习/复习产物按稳定 `artifactKey` 分视频持久化，而不是按“当前页面上次结果”或完整 URL 复用。YouTube 固定绑定 `videoId`，Bilibili 固定绑定 `BVID + 分P`；运行时 `mediaKey` 仍可精确到 CID 用于截图、转录等防串台操作，URL 只保存为来源信息，不承担主键职责。自动生成、外部规划截帧、手动补图等异步流程在开始时锁定 `tabId + mediaKey`，最终渲染和保存还会再次核对当前 `artifactKey`。SPA 切到新视频时先清空旧产物，再恢复当前视频自己的缓存；带来源 URL 的缓存若能证明属于另一视频也拒绝恢复。每个已生成/导入产物旁提供轻量“清空当前产物”，只删除当前视频当前任务，并同时清理该分P可能遗留的历史 CID 别名，方便纠正误导入。
- **Obsidian / Notion 图文包**：导出时新旧图片引用统一转换为 `images/` 下的标准 Markdown 图片路径，再打包为 `.zip`。
- **字幕校对形成完整闭环，而不是只导出 Prompt**：字幕页“校对”只打开工作流，不产生隐藏复制。用户明确点击“复制校对任务”后，SparkSub 把当前 cue 以 `L0001 | 文本` 形式发送给外部 AI；`Lxxxx` 直接复用现有时间轴，不再附加对校对无用的时间戳。外部 AI 只返回真正改动的行，导入时由 `applyPolishResult()` 生成稀疏 patch，未返回的字幕直接复用原文本和 `from/to`。应用前同时锁定 `tabId + mediaKey + selectedTrackId + cueRevision`，视频、轨道或字幕版本发生变化就拒绝旧结果。成功时先把每轨 sparse correction 写入独立 `bse_sub_corrections_<artifactKey>` 小记录，再更新页面权威字幕与内存 body cache；完整字幕正文仍单独由 `bse_sub_cache_<artifactKey>` 管理，正文刷新或 LRU 淘汰不会覆盖用户校对。SessionSnapshot 只是秒开优化，长字幕快照在空闲阶段合并写入，不阻塞“应用校对”的反馈。即使完整字幕超过正文缓存上限，correction overlay 仍可独立保留；下次重新拿到 base cues 后按时间锚点与原文安全重放。撤销最后一个 correction 时只删除对应 overlay，不误删仍有效的正文。本机 ASR 的声学 `aligning` 只用于形成时间轴；已有时间轴上的文字校对不重复跑昂贵音频对齐。
- **不再维护第二套经典 Prompt 库**：学习/复习六种产物统一由 AI 工作台的 mode prompt 构建器负责，外部 AI 也复用同一任务语义；字幕校对的内置精修与外部协作共用同一 `generateSubtitlePolishPrompt()` 协议和 `applyPolishResult()` 回填 seam。播放器旁滚动面板不再展开旧的讲义/摘要/要点/复盘 Prompt 网格，而是直接进入 Side Panel 学习工作区。

### 4. 订阅追踪中心与无人值守自动抓取 (Tracker & Unattended Harvest)
- 一键订阅关注 UP 主或专题课程合集。
- **追踪中心按“收件箱”而不是“最近 N 条列表”工作**：每个视频/分 P 都有稳定身份与独立 `isRead` 状态；用户打开某一条，只消费这一条。重复点击、跨窗口重复写回都必须幂等，不得顺带改变其他未读项。
- **巡检是增量发现，昂贵处理也是增量的**：后台 Alarm 可以重新读取订阅源的轻量目录来判断是否变化，但只有此前未见、且高于用户已读水位线的真正新增条目才进入未读与自动字幕提取流程。已经看过、已经缓存或只是平台回填出来的旧条目不能重新计算。
- **`unreadCount` 只是逐条状态的摘要，不是真值源**：筛选、徽标、排序、“合并复制未读”和卡片展开都从真实未读条目派生，不再假设“列表前 N 条就是未读”。卡片默认只展示最近 3 条以控制高度；存在更多历史时必须显示“查看其余 N 条”，用户可在原卡片内展开并再次收起，不能因为折叠而让历史入口消失。
- **批量导出与追踪账本职责分离**：打开合集/播放列表的批量目录只能补充已知条目的标题、时长、CID 等元数据，不得用目录结果整体覆盖追踪条目，也不得因此清掉 `isRead`、字幕缓存或制造新更新。新条目的发现统一由 Tracker 巡检负责。
- **多 P 使用稳定页级身份**：同一 BV 存在多个分 P 时，p1 也使用与后续页一致的 `BV...:p1` 形式；用于再次查询 Bilibili view API 的 `latestBvid` 只保存纯 BV 根标识。旧版 p1 的纯 BV 记录在巡检时就地迁移并保留已读/字幕状态。
- 卡片内支持逐条打开、逐条标为已读、按需加载字幕预览，以及只针对当前真实未读集合的 Markdown 合并复制；整卡“全部已读”是显式的批量消费动作。追踪账本只保存轻量元数据，字幕正文按媒体键单独缓存，避免一次已读操作重写整批字幕正文。
- **作者头像允许迟到并自愈**：视频页首屏的作者区域可能尚未完成懒加载，不能把一次空 `img.src` 当成永久结果。当前视频优先读取页面状态与懒加载图片属性；B站若已有姓名/合集但缺头像，仍继续通过 `view` API 补齐 `owner.face`。历史订阅若早期保存时缺头像，只对少量可修复卡片做轻量元数据回填并持久化，不触发整库重算或字幕重新提取。
- 扩展徽标未读红点与系统桌面通知同样读取逐条状态派生出的未读总数，保证与追踪页一致。

### 5. 后台整视频转录

- Bilibili/YouTube 视频无需打开或播放即可完成平台字幕抓取；YouTube 关闭页链路由 host 的固定版 `yt-dlp` 完成。
- 平台字幕为空时，对支持语言调用本机 CoreML；粤语保持平台字幕限定。
- 任务具备单执行器租约、崩溃恢复、移除/清空/重试取消、长任务心跳和非空结果门槛。
- 能力面板区分未安装、部分就绪、组件可用和模型不兼容。
