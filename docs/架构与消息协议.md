# 架构与消息协议

## 一、责任边界

| 模块 | 责任 | 不应承担 |
| --- | --- | --- |
| `background/service-worker.js` | 观察 YouTube 字幕请求、保存标签页短期状态、转发命令、白名单代理哔哩哔API、Alarms 定时巡检与 Badge 管理 | 解析字幕、操作页面 DOM、代理任意未知网址 |
| `content/main-world-bridge.js` | 从 YouTube 播放器实例读取实时轨道，请求播放器切换轨道 | 渲染界面、持久化数据、替换全局网络函数 |
| `platform/*.js` | 屏蔽 YouTube/哔哩哔接口差异，输出统一轨道与字幕数组、选集拓扑分析与 DASH 直链 | 操作双界面 |
| `core/parsers.js` / `formatters.js` | 纯解析、时间定位、格式化 (Markdown/SRT/VTT) 和通用工具 | 依赖具体页面结构 |
| `core/tracker.js` | 纯 JS MD5, WBI 签名加密, YouTube RSS 解析, 环形缓冲, 自动字幕拉取与存储 | 操作具体 UI 界面 |
| `content/app.js` | 当前标签页唯一状态源、路由调度、取消旧任务、播放同步、作者与合集元数据提取 | 包含大段平台特定解析代码 |
| `content/rolling-panel.js` | 播放器旁紧凑滚动面板（Shadow DOM 隔离） | 直接请求字幕接口 |
| `sidepanel/*` | 完整搜索、跳转、复制、AI总结、导出与订阅追踪看板 | 拥有另一套独立字幕状态 |

## 二、核心状态

`content/app.js` 是当前标签页的唯一状态源，状态主要字段为：

```text
platform          平台 (youtube / bilibili)
mediaKey          规范化视频标识
status            idle / loading / ready / empty / error
isRefreshing      已有字幕时的非破坏性后台刷新
revision          单调递增的状态版本，拒绝旧状态回写
cueRevision       仅在新字幕正文提交时递增，避免诊断更新重建大列表
tracks            字幕轨道列表
selectedTrackId   当前轨道
cues              统一字幕数组
activeIndex       当前播放句
authorInfo        作者名字、MID/ChannelID、头像、合集ID与名称
diagnostics       不含令牌的阶段日志
lastError         阶段 / 错误代码 / 消息 / 处理建议
```

滚动面板和侧边栏只消费这份状态，不各自请求字幕，从而保证轨道、当前句和错误状态一致。

## 三、消息协议

| 消息 | 方向 | 用途 |
| --- | --- | --- |
| `BSE_CAPTION_REQUEST_CAPTURED` | 后台 → 页面 | 通知页面捕获到的 YouTube 原生字幕请求 |
| `BSE_GET_CAPTURED_REQUESTS` | 页面 → 后台 | 恢复当前标签页的字幕请求地址 |
| `BSE_FETCH_BILIBILI_RESOURCE` | 页面/侧边栏 → 后台 | 仅读取白名单内的哔哩哔 API/CDN JSON 资源 |
| `BSE_DOWNLOAD_MEDIA_FILE` | 页面/侧边栏 → 后台 | 调用 Chrome Downloads 管理器代理下载媒体文件 |
| `BSE_STATE_UPDATE` | 页面 → 后台 | 发布轨道、字幕和诊断状态 |
| `BSE_PLAYBACK_UPDATE` | 页面 → 后台 | 仅发布高频变化的当前句索引 |
| `BSE_STATE_BROADCAST` | 后台 → 侧边栏 | 将完整状态同步给侧边栏 |
| `BSE_PLAYBACK_BROADCAST` | 后台 → 侧边栏 | 更新当前句，避免反复传输全部字幕 |
| `BSE_COMMAND_ACTIVE_TAB` | 侧边栏 → 后台 | 将跳转、切轨和刷新命令发给当前视频页 |
| `BSE_TRACKER_UPDATE_BADGE` | 侧边栏/页面 → 后台 | 根据未读订阅数同步扩展图标徽标文字 |
| `BSE_TRACKER_RESET_ALARM` | 侧边栏 → 后台 | 根据用户配置重新调度 Alarms 巡检周期 |
| `BSE_TRACKER_CHECK_NOW` | 侧边栏 → 后台 | 手动立即触发全量订阅源增量检测与字幕抓取 |

### 播放同步性能契约

- 内容脚本每 180ms 检查一次播放位置，但只在当前句索引变化时跨进程发布。
- 播放更新只携带 `activeIndex` 和 `currentTime`，不重复传输完整字幕。
- 面板和侧边栏仅更换前后两个高亮节点；只有 `cueRevision` 变化时才重建字幕 DOM。
- 页面隐藏时暂停播放与路由轮询；手动滚动后保持“恢复跟随”，只有用户点击恢复或点击字幕跳转才会重新跟随。
- 平滑滚动的整个动画期间都标记为程序滚动，避免 YouTube 广告切换或布局抖动将其误判为用户操作。
- YouTube 前贴片或中插广告复用播放器时暂停时间轴同步，保留广告前的字幕高亮，正片恢复后再继续跟随。

## 四、必须维持的不变量

1. 只有 `cues.length > 0` 时才能进入 `ready`。
2. 每次媒体切换都必须提高任务代数并取消旧请求。
3. 旧媒体或旧轨道的结果不得写入当前状态。
4. 诊断不得包含完整字幕网址、签名或 PO Token。
5. 页面主世界通信桥不得替换 `fetch` 或 `XMLHttpRequest`。
6. 用户手动滚动后，自动跟随不得立即抢回滚动位置。
7. 已有字幕刷新时不得清空正文；失败后必须回到可用状态并保留旧结果。
8. 后台不得接受非哔哩哔视频页发起的代理请求，也不得访问白名单外域名。
9. 订阅追踪系统每个订阅源最多保留 20 条历史记录（FIFO 环形缓冲），防止 LocalStorage 无限膨胀。
10. 无人值守后台抓取必须捕获并封装异常，单视频字幕失败不得中断全量巡检流程。

## 五、后续扩展方式

- 新增平台时，实现与 `discoverTracks` / `loadTrack` 相同的适配器边界。
- 新增导出格式时，只修改 `core/formatters.js` 与侧边栏选项。
- 迁移批量导出时，使用独立任务模块，不将批量队列写入当前视频状态。
- 新增订阅平台时，在 `core/tracker.js` 中扩充增量比对与 `fetchItemSubtitle` 适配器。
