# 架构与消息协议

## 一、责任边界

| 模块 | 责任 | 不应承担 |
| --- | --- | --- |
| `background/service-worker.js` | 观察 YouTube 字幕请求、保存标签页短期状态、转发命令、白名单代理哔哩哔API、Alarms 定时巡检与 Badge 管理 | 解析字幕、操作页面 DOM、代理任意未知网址 |
| `content/main-world-bridge.js` | 从 YouTube 播放器实例读取实时轨道，请求播放器切换轨道 | 渲染界面、持久化数据、替换全局网络函数 |
| `platform/*.js` | 屏蔽 YouTube/哔哩哔接口差异，输出统一轨道与字幕数组、选集拓扑分析与 DASH 直链 | 操作双界面 |
| `core/parsers.js` / `formatters.js` | 纯解析、时间定位、格式化 (Markdown/SRT/VTT) 和通用工具 | 依赖具体页面结构 |
| `core/batch-export.js` | 统一批量条目选择、结果排序、复制/合并文件/ZIP 输出投影与最终投递 Interface | 抓取平台字幕、理解 B站/YouTube 原始接口 |
| `core/tracker.js` | 纯 JS MD5, WBI 签名加密, YouTube RSS 解析, 环形缓冲, 自动字幕拉取与存储 | 操作具体 UI 界面 |
| `core/queue.js` | 持久任务、执行租约、平台字幕优先级、本机 ASR 回退与结果落盘 | 直接建立 Native Messaging 连接、持久化 Bilibili 签名音频 URL |
| `core/queue-orchestrator.js` | 合并并发唤醒，保证单飞执行与尾部补跑 | 解析字幕或拥有第二套队列状态 |
| `core/native-host.js` | 复用 Native Messaging Port、请求关联、活动看门狗、分块结果校验 | 传输媒体字节、读取 Cookie、直接渲染 UI |
| `content/app.js` | 当前标签页唯一状态源、路由调度、取消旧任务、播放同步、作者与合集元数据提取 | 包含大段平台特定解析代码 |
| `content/rolling-panel.js` | 播放器旁紧凑滚动面板（Shadow DOM 隔离） | 直接请求字幕接口 |
| `sidepanel/*` | 完整搜索、跳转、复制、AI总结、导出与订阅追踪看板 | 拥有另一套独立字幕状态 |
| `native/SparkSubHost` | **兼容/回滚 Native Messaging 实现**：保留 v1/v2、旧 macOS 14+ 本机执行和故障回退 | 作为默认模型策略或继续扩展新的浏览器执行能力；默认执行已由 SparkScribe bundled helper 承接 |

## 二、核心状态

`content/app.js` 是当前标签页的唯一状态源，状态主要字段为：

```text
platform          平台 (youtube / bilibili)
mediaKey          规范化视频标识
status            idle / loading / ready / empty / error
isRefreshing      已有字幕时的非破坏性后台刷新
revision          单调递增的状态版本，拒绝旧状态回写
cueRevision       仅在新字幕正文提交时递增，避免诊断更新重建大列表
tracks            字幕轨道列表
selectedTrackId   当前轨道
cues              统一字幕数组
activeIndex       当前播放句
authorInfo        作者名字、MID/ChannelID、头像、合集ID与名称
diagnosticSessionId 当前媒体诊断会话标识
diagnostics       已脱敏的 DiagnosticEvent[] 结构化阶段日志
lastError         阶段 / 错误代码 / 消息 / 处理建议
```

滚动面板和侧边栏只消费这份状态，不各自请求字幕，从而保证轨道、当前句和错误状态一致。

### 结构化诊断契约

每条 `DiagnosticEvent` 包含 `level`、`scope`、`code`、`stage`、`message`、`sessionId`、时间戳和白名单 context。当前视频使用 `media` scope；侧栏另外隔离 `queue`、`native` 和 `batch`。所有事件必须经过共享 store 的 `append()`，统一执行脱敏、短窗去重、单会话裁剪和总量裁剪，UI 不得直接维护字符串日志数组。

默认诊断视图显示 `info`、`warn` 和 `error`，详细视图才显示 `debug`。HTTP 状态、接口通道、CID、缓存和挂载调度属于 debug；预期降级属于 info 或 warn；只有工作流最终失败使用 error。侧栏复制日志时只复制当前选择的 scope 和活动会话。

## 三、消息协议

| 消息 | 方向 | 用途 |
| --- | --- | --- |
| `BSE_CAPTION_REQUEST_CAPTURED` | 后台 → 页面 | 通知页面捕获到的 YouTube 原生字幕请求 |
| `BSE_GET_CAPTURED_REQUESTS` | 页面 → 后台 | 恢复当前标签页的字幕请求地址 |
| `BSE_FETCH_BILIBILI_RESOURCE` | 页面/侧边栏 → 后台 | 仅读取白名单内的哔哩哔 API/CDN JSON 资源 |
| `BSE_DOWNLOAD_MEDIA_FILE` | 页面/侧边栏 → 后台 | 调用 Chrome Downloads 管理器代理下载媒体文件 |
| `BSE_STATE_UPDATE` | 页面 → 后台 | 发布轨道、字幕和诊断状态 |
| `BSE_PLAYBACK_UPDATE` | 页面 → 后台 | 仅发布高频变化的当前句索引 |
| `BSE_STATE_BROADCAST` | 后台 → 侧边栏 | 将完整状态同步给侧边栏 |
| `BSE_PLAYBACK_BROADCAST` | 后台 → 侧边栏 | 更新当前句，避免反复传输全部字幕 |
| `BSE_COMMAND_ACTIVE_TAB` | 侧边栏 → 后台 | 将跳转、切轨和刷新命令发给当前视频页 |
| `BSE_TRACKER_CHECK_NOW` | 侧边栏 → 后台 | 手动立即触发全量订阅源增量检测与字幕抓取 |
| `BSE_QUEUE_ENQUEUE` | 扩展页面 → 后台 | 写入 URL 与明确的 `sourceLanguage`，随后唤醒唯一队列执行器 |
| `BSE_QUEUE_RETRY` / `REMOVE` / `CLEAR_ALL` | 扩展页面 → 后台 | 由唯一执行器先取消活动任务，再原子修改队列 |
| `BSE_ORCHESTRATOR_NOTIFY` | 扩展上下文 → 后台 | 仅发送“可能有工作”信号；调用者不直接执行队列 |
| `BSE_NATIVE_CAPABILITIES` | 侧边栏 → 后台 | 通过可信扩展页代理读取 host、yt-dlp、Parakeet、Cohere 状态 |
| `BSE_NATIVE_CANCEL` | 侧边栏/队列 → 后台 | 通过 Service Worker 代理取消指定本机任务 |
| `BSE_CAPTURE_FRAME` | 侧边栏 → 页面 | 单点原画 Canvas 截帧；异步操作可携带 `expectedMediaKey`，页面只在当前媒体身份一致时执行并在响应中回传 `mediaKey` |
| `BSE_CAPTURE_BEST_FRAME` | 侧边栏 → 页面 | 在规划窗口内采样少量真实画面，按稳定性/细节/曝光选择代表帧；同样受 `expectedMediaKey` 约束并恢复原播放状态 |
| `BSE_FETCH_LOCAL_LLM` | 页面/侧边栏 → 后台 | 代理请求 `http://localhost` / `http://127.0.0.1` 本地 AI 网关，支持 Bearer Auth；不承担任意公网代理 |

## 四、AI 图文报告与多模态视频理解流水线

SparkSub 把“理解视频”“找画面”“筛证据”“写报告”分成清楚的职责，而不是让一个提示词同时承担所有事情：

1. **阶段一：基于字幕的时间窗口规划 (Transcript Sampling Planning)**：
   * 输入当前视频完整的带时间戳字幕 `cues[]`。发给模型的字幕使用 `00:12  文本` 这种普通时间列，不再用 `[00:12]` 与机器标记、图片占位符混在一起；
   * 这一层只做文本语义分析与时间窗口推断：模型根据字幕中的指代表达、内容缺口和主题语义，判断哪些时段值得自动化播放器后续取样，不承担媒体读取、取帧或真实内容判断；
   * 新规划协议输出 `samplingWindows[]`，使用 `windowStart / windowEnd / targetSec / contentHint / samplingGoal / reason / importance` 描述“在哪个时段取样、希望补充什么、字幕依据是什么”。不再让新提示词暴露 `visualRequests / visualEvidence` 这类容易把文本规划与媒体执行混在一起的字段；
   * 可以为高价值内容给出较多候选窗口：理工中的图形/推导线索、软件中的界面/代码线索、人文历史中的人物/文献/地点线索等都可以触发窗口规划；纯口述且字幕已经完整承载信息时则无需安排取样；
   * `normalizeSamplingWindows()` 是规划协议到媒体执行层的翻译 seam：新 `samplingWindows` 与历史 `visualRequests / visualEvidence` 都在这里归一，因此旧外部规划 JSON 继续兼容，而新模型交互使用更准确的能力语义；
   * 请求失败与返回格式失败必须区分：认证/网络/模型调用失败直接终止本次生成；模型已成功返回但规划 JSON 不合法时，才允许降级为“字幕 + 用户手动画面”继续合成。
2. **阶段二：窗口内真实筛帧 + 跨窗口证据精简 (Visual Candidate Selection)**：
   * 每个媒体执行请求通过 `BSE_CAPTURE_BEST_FRAME` 在目标附近最多取 3 个候选秒数；候选只生成约 `64×36` 的灰度像素签名，比较帧间变化、边缘细节与曝光。进入跨窗口去重前再压缩成保留二维空间结构的约 128 维网格 fingerprint，避免白底 PPT、代码页或公式页仅因整体灰度接近就被误判成同一画面；
   * 显式 seek 只有在播放器确认目标画面已经完成寻道/解码后才允许编码高清帧。seek 超时或最终编码前再次寻道失败都会明确返回失败，不把 currentTime 已变化但 Canvas 仍可能是旧画面的状态冒充成功截图；
   * 最终证据帧使用约 `1536px` 最大宽度与 `WebP 0.90` 质量，优先保住代码、公式、文献和小字号幻灯片细节；候选阶段仍然只处理低分辨率签名，因此提高最终图质量不会把多候选成本同步放大；
   * 每个窗口得到的高清图先作为**本次运行时候选**存在内存。所有窗口结束后，再按近重复度、视觉质量、重要性和时间覆盖做一次全局筛选；近重复判断会检查最近时间范围内已经保留的候选，而不是只和相邻上一张比较，因此 `A → B → A` 这类重复也能识别。用户手动截图优先保留，自动截图的预算随视频时长动态增长，默认约 6～24 张；
   * `selection.fingerprint`、视觉评分和候选签名只服务当前筛选，不写入长期缓存。`source`（手动/规划）、`importance`、`evidenceGoal` 这类少量语义元数据可以随最终图片保存，以便重开后仍尊重用户手动画面的优先级；未进入最终证据集的自动候选不会送给多模态模型，也不会进入 AI Note IndexedDB；外部规划托盘允许保留更宽的候选集合，但超过阈值后先做一轮宽松初筛；
   * 像素读取受限时明确退回纯时间启发式，并以 `selection.strategy = 'time-fallback'` 标记，不把时间猜测描述成视觉检测成功。
3. **阶段三：内容自适应的多模态报告合成 (Multimodal Synthesis)**：
   * 只把筛选后的字幕脉络和高价值画面传入多模态模型。最终写作先遵循视频自己的逻辑，再根据内容类型决定结构：数学/理工强调对象、推导、条件与边界；软件强调目标、操作、状态与失败场景；人文社科强调事实、观点、论据、背景和不同视角；访谈、评论、艺术与纪录片使用与内容匹配的叙事结构；
   * 图片引用采用普通 Markdown 形式 `![简短说明](frame://01:15)`。`frame://` 是 SparkSub 内部图片引用 seam，渲染和 ZIP 导出时再解析成真实图片；历史缓存中的 `[SCREENSHOT: 01:15 "说明"]` 继续兼容，但新提示词不再要求模型生成这种方括号标记；
   * 数学公式只在内容确实需要时使用常规 LaTeX。画面模糊、公式不清或图例无法辨认时要求直接说明不确定性，不从模糊视觉证据补造细节。
4. **呈现、导出与缓存 (Presentation, Export & Cache)**：
   * 侧边栏将 AI/外部导入 Markdown 当作不可信文本处理：原始 HTML 默认转义；表格单元格逐格转义后只恢复受控表格结构；图片 URL 仅接受 `http(s)`、`blob:` 与有限的 `data:image/*;base64` 类型，禁止 `javascript:` 与 SVG Data URL 注入；
   * 报告内图片使用 `contain` 完整显示，不再用固定 `220px + cover` 裁掉板书、文档或代码内容；点击缩略图打开原图预览层，`▶ MM:SS` 按钮单独负责跳回视频，避免同一个点击既表示“放大”又表示“跳播”；
   * `transformFrameReferences()` 负责识别新旧图片引用，`resolveFrameEntry()` 负责把引用时间解析到真实截图。渲染、删除和 ZIP 导出共用这两个 seam；精确时间不存在时只在约 ±5 秒内选择真正最近的一张，避免页面显示、删除和导出对同一个 `frame://` 得出不同答案；
   * `frame://` 的时间是报告中的语义槽位，真实截图时间可能略有偏移。图片卡片和跳播展示/使用真实截图时间，同时删除仍保留原引用时间，从而既不伪造截图秒数，也能准确删除原 Markdown 引用；
   * 外部网页 AI 不再提供“拖拽全部”这种跨 Side Panel → 网页上传框的不可靠文件传输承诺。直接投递改为**复制精选拼图**：底层布局也硬限制最多 4 张，1～2 张单列、3～4 张双列，画布宽约 `1152px`，竖屏/文档图也在受控高度内等比缩放；需要全部原始分辨率时使用“原图打包” ZIP；
   * 阶段二外部合成提示词只引用用户**最后一次实际投递**的图片集合：联系表按真正成功绘制进去的图片生成提示词，原图包则按已打包原图生成更宽的证据集。不会再出现“提示词列出 12 张、网页版实际只收到 4 张”的输入协议错位；
   * 联系表只服务剪贴板投递，不替代原图缓存。它严格限制总尺寸，避免无限纵向长图在视觉模型侧被整体缩小后让文字、公式和代码失去可读性；
   * 点击图片右上角 `▶ MM:SS` 可回跳视频对应画面；导出时 `frame://` / 旧 `[SCREENSHOT]` 引用统一转换为 `images/...` 的标准 Markdown 图片路径；
   * 讲义 Markdown 按 `mediaKey` 存于 `chrome.storage.local`，最终选中的截图二进制存入 IndexedDB。保存时先写一套带版本 ID 的新图片集，不覆盖旧图；随后在一次 `chrome.storage.local.set()` 中提交 Markdown 指针与 LRU 索引，提交失败就删除本次新图片，提交成功后才清理旧图片。相同 `mediaKey` 的保存串行执行，避免补图/删除交错覆盖；
   * 缓存继续受数量、总图片字节与 30 天有效期回收策略约束；只保存最终图片及少量来源/用途元数据，质量 fingerprint、评分与临时候选不持久化。

### 媒体身份与异步操作不变量

- **媒体身份是 `tabId + mediaKey`，不是“当前活动页面”这个瞬时概念**。自动生成、外部规划截帧、手动截帧与占位补图在开始时锁定这一身份；后续请求发送到启动时的标签页，而不是每一步重新查询当前活动 tab。
- 页面侧收到 `expectedMediaKey` 后再次核对自身状态，响应也带回实际 `mediaKey`；Side Panel 在发送前、响应后和最终提交前都会检查上下文。一旦用户切视频或切标签页，旧任务立即停止，其截图、报告、toast 和进度清理都不能覆盖新任务。
- AI Note 缓存恢复带 revision。旧视频的慢速缓存读取即使晚到，也不能重新覆盖新视频的报告 DOM。
- Service Worker 的 `BSE_GET_ACTIVE_STATE` 会重新查询真实活动 tab；`getTabState()` 只有在 `isSameMediaOrUrl()` 明确证明缓存仍属于当前媒体时才允许回退。SPA 切到新视频、或退回站点普通页面后 content script 暂时失联，不会重新返回上一媒体缓存。

### AI 提示词协议

- **自然语言优先，机器结构最小化**：学习报告、摘要、复盘题和 ASR 校对都使用普通 Markdown / 自然中文描述；只有客户端必须解析的规划结果使用 JSON。目标是减少提示词歧义和无意义的“系统级语气”，不是绕过任何安全机制。
- **三种语法分工明确**：字幕时间使用 `00:12  文本`；ASR 逐句回填使用 `L0001 | 文本`；报告图片使用 `![说明](frame://00:12)`。三者不再共享方括号命名空间。
- **保持兼容但不继续扩散旧协议**：ASR 解析器继续接受旧 `[1] 文本`，报告渲染/删除/导出继续接受旧 `[SCREENSHOT: ...]`，因此历史缓存和旧模型返回不会突然失效；所有新生成提示词只使用新格式。
- **内容自适应，不用数学模板统治所有视频**：提示词不要求每个视频都输出“定理、避坑、解题动作”。章节、总结、清单、复盘题和图片密度都由内容决定。

### AI 配置与模型状态契约

- **已保存模型是生成事实源**：顶部模型徽标始终显示当前已保存的生成模型，服务目录探测不得把它自动改成“推荐模型”。编辑框存在未保存修改时，生成按钮拒绝继续，避免用户以为新模型已经生效。
- **“服务探测”和“测试当前模型”是两件事**：`probeLlm()` 只读取 `/models` / Ollama `/api/tags`，用于协议和模型目录提示；`testLlm()` 会对输入框里的准确模型发送一次最小文本请求，并返回请求模型、服务实际返回模型、延迟和短响应摘要。测试不会自动保存配置。
- **模型目录不是最终真值**：网关可能隐藏模型列表或允许别名路由，因此“目录未发现”只显示提醒；只要实际模型调用成功，测试仍报告可用，同时把 `requestedModel → returnedModel` 的路由差异展示给用户。
- **文本测试不等于视觉能力测试**：图文讲义仍要求所选模型支持图片输入；设置面板必须明确这一边界，不用一次文本 Ping 冒充多模态能力验证。
- **网络权限保持最小化**：当前 Manifest 只授权本地 AI 网关，配置层拒绝把任意公网 Base URL 当成可直连端点。云端模型应由用户自己的本地 OpenAI-compatible 网关转发；除非以后另行设计可解释的 optional host permissions，不扩大到全网访问。
- **超时语义一致**：后台代理遵守调用方的短探测超时（下限 1 秒、上限 300 秒），不再把 3–15 秒的探测强制拖到至少 60 秒；正式生成继续使用配置中的长任务超时。

## 五、后台队列与 Native Messaging

Service Worker 是 `processPendingJobs()` 的唯一调用者。入队、重试、扩展启动和相关存储变化只负责唤醒 orchestrator；同一时刻最多有一次 drain，执行期间的新唤醒会合并为一次尾部补跑。

队列持久化以“索引 + 每任务独立记录”为源数据，不在常规读取时扫描整个 `storage.local`。存储结构带 schema 版本，只有旧数组、旧索引或 schema 升级时才执行深度清洗迁移；完成任务只落盘规范化 cue，Markdown/TXT/SRT 作为确定性投影按需恢复并受内存预算约束，避免多份长文本重复占用持久存储。

队列存在两种明确处理意图，不能混用：`auto` 走“人工平台字幕 → 自动 CC/ASR → 平台翻译字幕 → YouTube 原生 Transcript → 本机 ASR”的 caption-first 策略；`local-asr` 表示用户明确要求离线转录，必须跳过打开标签页字幕、`stageArtifacts` 字幕缓存、平台字幕接口和 YouTube 原生字幕查询，直接对当前目标媒体执行本机 ASR。播放器与 Side Panel 的“离线转录”按钮必须发送 `processingIntent: 'local-asr'`，普通批量任务默认仍为 `auto`。YouTube 页面链路耗尽后，host 会通过固定版 `yt-dlp` 在后台重新盘点相同优先级，逐轨下载并验证 JSON3/VTT；坏轨清理后继续下一轨，因此标签页关闭或首轨损坏都不等于“无字幕”。只有规范化后至少一条 cue 且纯文本非空，任务才进入 `done`。结果同时保存语言与 `manual / auto / translated` 类型。Bilibili 的 CDN 签名地址只存在于当前执行内存；崩溃恢复会重新解析，不从存储复用过期签名。

扩展与 `com.sparksub.transcriber` 当前使用 **`sparkscribe.browser-native/2`**。Host 名保持 SparkSub 作用域，用来表示浏览器集成端点；它不等于 SparkScribe 的 App Bundle ID。

- 请求动作仍保持最小集合：`capabilities`、`ping`、`youtubeCaptions`、`transcribe`、`cancel`；每条都带唯一 `requestId`，长任务另带 `jobId`。`youtubeCaptions` 可携带受限枚举 `subtitlePreference`（`manual-first / manual-only / ai-first`）。
- **v2 capability 只描述能力，不暴露具体模型路由**：`features.localASR.languages`、`youtubeCaptions`、`remoteMedia`、`cancellation`、`chunkedResults`。浏览器不得依据 Qwen / Parakeet / Cohere / sherpa 等模型名决定语言或执行路径。
- SparkSub 默认先发协议 v2。只有 Host 明确返回 `PROTOCOL_MISMATCH` 时才允许回退一次 v1；超时、断连、坏结果或普通执行错误不得触发旧协议回退。standalone `SparkSubHost` 继续接受 v1/v2，并把 v1 的 `ytDLP + models.*` 能力立即归一成 v2 的 feature view。
- `engine` 只是可选的机器诊断标识，`engineLabel` 只是可选显示文案；二者都不是路由输入。语言支持以 `features.localASR.languages` 为事实源，因此未来 SparkScribe 增加粤语模型时不需要再改浏览器路由代码。
- 进度携带 `requestId`、`jobId`、稳定 stage、percent 与脱敏 hint，并续期队列租约及 JS 活动看门狗。
- 结果：`resultBegin` → 有序编号的 `resultChunk` → `resultEnd`。扩展验证分块数量、序号、cue 时间和非空正文后才提交。
- 原生 host 单条输出严格小于 900 KiB；输入帧上限 64 MiB；媒体文件从不经过 Native Messaging。
- 转录阶段 host 周期性发心跳。扩展使用 15 分钟静默看门狗；真正超时时先发送同一协商版本的 best-effort `cancel(jobId)`，再以稳定错误结束。
- 活动或并发请求复用同一 Native Messaging Port；最后一个请求结束 250 ms 后自动断开，避免空闲端口持续保活 Service Worker 与 Swift host。能力快照保留在内存，不因空闲断开而重新启动 host。
- 每个本机任务使用独立 UUID 临时目录并在结束或取消时清理；host 启动时只回收 SparkSub 自有临时根目录下超过 24 小时的 UUID 目录，不触碰其他命名目录。
- 正常模式 stdout 只写小端长度前缀 JSON 帧。SparkScribe bundled helper 自身保持轻量，重 ASR 通过 `SparkScribe --browser-inference-worker` 执行；worker 在模型推理期间从文件描述符层隔离第三方 stdout，再仅返回一个私有 JSON envelope。standalone `--diagnose` 仍是兼容 Host 的非分帧诊断模式。

完整消费侧契约见 `docs/native-contract-v2.md`。SparkScribe 侧使用同一 Contract ID 与字段语义；默认安装器在 bundled helper readiness 完整时将 Chrome manifest 指向 `/Applications/SparkScribe.app/Contents/Helpers/SparkSubNativeHost`，否则回退 standalone Host。

YouTube 只接受规范的 `https://www.youtube.com/watch?v=<11位ID>` 公共地址；标签页解析必须同时证明请求 videoId、当前 URL、`state.mediaKey` 与 MAIN-world 返回 `videoId` 一致。SparkScribe-owned `yt-dlp` runtime 固定版本与 SHA-256，使用参数数组而非 shell，也不读取浏览器 Cookie；平台字幕与媒体获取都被限制在独立 job workspace。Bilibili 的媒体身份以精确 `BVID + CID` 为准：当前页面发起 `local-asr` 时必须先拿到 `bili:<BVID>:cid<CID>`，Queue 每次执行再通过 view API 重新解析 BVID→page→CID；`stageArtifacts` 只有 owner mediaKey 与权威身份完全一致时才允许复用，打开标签页状态也必须精确匹配同一 BVID+CID。playurl 返回若声明了其他 BVID/CID 或音频时长明显不符，必须在调用 SparkScribe 前 fail-closed。Bilibili 远程音频仍只接受白名单 HTTPS CDN 和受限请求头。

SparkScribe 的 Media Queue、Live Captions 与 Browser Worker 共用跨进程 inference lease；资源占用冲突返回稳定 `BUSY`，不会同时加载第二套大型本地模型。standalone Host 的旧模型目录逻辑只作为兼容路径维护。

## 六、运行时性能契约

- 内容脚本以原生 `timeupdate` 事件作为播放同步主路径，并用 `requestAnimationFrame` 合并同一帧内的更新；500ms 轻量轮询只负责发现播放器元素替换并重新挂接监听器。
- 只有当前句索引变化时才跨进程发布，播放更新只携带 `activeIndex` 和 `currentTime`，不重复传输完整字幕。
- 面板和侧边栏仅更换前后两个高亮节点；只有 `cueRevision` 变化时才重建字幕 DOM。
- 页面隐藏时暂停播放与路由轮询；手动滚动后保持“恢复跟随”，只有用户点击恢复或点击字幕跳转才会重新跟随。
- 平滑滚动的整个动画期间都标记为程序滚动，避免 YouTube 广告切换或布局抖动将其误判为用户操作。
- YouTube 前贴片或中插广告复用播放器时暂停时间轴同步，保留广告前的字幕高亮，正片恢复后再继续跟随。
- Feed 注入器首次加载允许一次全量扫描；之后 MutationObserver 只扫描新增节点、最近卡片祖先和新增子树。突发变更根超过阈值时才回退一次全量扫描，禁止每个 mutation burst 对无限信息流重复执行全页 `querySelectorAll`。
- 队列持久层只保存规范 cue 与任务状态；TXT/Markdown/SRT 等确定性派生文本放入有字符预算的运行时 LRU，侧栏预览按展开时才物化。Runtime 消息与 storage change 的重复刷新必须合并为 single-flight。
- AI 视觉筛帧在单个请求窗口内只用低分辨率灰度签名比较候选秒数，并只编码该窗口最终 1 张高清图；多个窗口产生的高清候选只在本次生成内存中继续做全局去重/覆盖筛选。只有最终证据集进入多模态请求与 AI Note IndexedDB；fingerprint、评分和被淘汰候选不持久化。AI Note 索引继续使用已持久化的大小元数据完成回收判断，不为统计容量反复读取所有正文与图片。

## 七、类型与执行上下文边界

- Chrome MV3 的 Service Worker、content script、MAIN-world bridge、sidepanel 与平台脚本属于不同执行上下文。`tsconfig.json` 使用 `moduleDetection: "force"` 与 bundler module resolution 让 `checkJs` 按文件隔离分析，禁止为了消除虚假的全局重名错误而给运行时代码增加无意义 namespace 包装。
- DOM 类型必须在真实 seam 收窄：侧边栏使用集中元素注册表，滚动面板通过 `requireElement(selector, ctor)` 同时做模板运行时校验和具体元素类型收窄；委托事件先把 `EventTarget` 收窄成 `Element` / `HTMLInputElement`。禁止用全局 `any`、`@ts-ignore` 或给所有 `HTMLElement` 添加私有字段来压平类型债。
- Native Host 转录结果使用显式 `{ cues, engine }` 对象；不得继续给数组动态挂 `engine` 属性。调用端与类型声明必须共享同一结果模型。
- Bilibili 与 YouTube 批量目录统一归一到 `BatchMediaTree`；平台适配器负责消化原始拓扑差异，侧栏/批量 UI 不维持两套结构分支。
- `getMediaKey(platform, url)` 的显式 URL 是契约的一部分。后台判断标签页媒体时不得静默回退到当前扩展上下文的 `location` / DOM。
- Bilibili 与 YouTube 的平台 Module 只负责把原始目录和字幕抓取结果归一成 `BatchMediaTree` / `BatchItemResult`。条目范围选择、稳定排序、Manifest、复制长文本、合并 Markdown/TXT 与 ZIP 的组织规则统一由 `core/batch-export.js` 承担；Side Panel 和播放器旁面板只是两个 delivery Adapter，不得再让平台 Module 直接触发文件下载。
- YouTube 批量字幕请求必须把用户的 `manual-first / manual-only / ai-first` 偏好和 `AbortSignal` 透传到 Native Host。取消批量任务必须取消正在执行的 `youtubeCaptions` 作业，而不只是停止领取下一条。

## 八、必须维持的不变量

1. 只有 `cues.length > 0` 时才能进入 `ready`。
2. 每次媒体切换都必须提高任务代数并取消旧请求。
3. 旧媒体或旧轨道的结果不得写入当前状态。
4. 诊断不得包含完整字幕网址、签名或 PO Token。
5. 页面主世界通信桥不得替换 `fetch` 或 `XMLHttpRequest`。
6. 用户手动滚动后，自动跟随不得立即抢回滚动位置。
7. 已有字幕刷新时不得清空正文；失败后必须回到可用状态并保留旧结果。
8. 后台不得接受非哔哩哔视频页发起的代理请求，也不得访问白名单外域名。
9. 订阅追踪卡片默认只渲染最近 3 条记录，历史必须通过明确的“查看其余记录”入口在侧边栏内展开；UI 折叠不得等同于删除历史。普通订阅最多保留 20 条历史，合集可保留最多 100 条以支撑稳定增量差分与批量工作流。
10. 无人值守后台抓取必须捕获并封装异常，单视频字幕失败不得中断全量巡检流程。
11. 只有 Service Worker 可以执行队列；侧边栏、内容脚本与 Offscreen Document 只能入队或唤醒。
12. 平台字幕成功时不得下载音频或调用本机 ASR。
13. 本机语言支持必须读取协商后的 `features.localASR.languages`；未声明支持的语言在平台字幕耗尽后返回 `ASR_LANGUAGE_UNSUPPORTED`。不得在浏览器侧把粤语或任一语言永久绑定为“支持/不支持”，也不得据模型名猜路由。
14. Native Messaging 不得携带媒体字节、Cookie、Authorization 或持久化签名 URL。
15. 本机任务的取消、超时、EOF 和失败路径都必须清理任务专属临时目录。
16. 移除、清空或重试活动任务必须经 Service Worker 取消旧执行；旧租约不得覆盖新状态或复活已删除任务。
17. AI 视觉请求中的 `0` 秒是合法时间戳；窗口、目标秒数与截图时间必须用有限数值/空值判断，不得用 truthy/falsy 判断误丢视频开头的证据点。
18. 规划阶段可以宽覆盖视觉候选，但自动候选只有经过全局筛选后才能进入多模态请求和长期图片缓存；用户手动截图不得被自动去重逻辑静默删除。
19. 新提示词不得重新混用字幕时间、逐句回填 ID 与图片引用语法；`00:12  文本`、`L0001 | 文本`、`frame://00:12` 分别承担独立职责。
20. Tracker 的逐条 `isRead` 是已读状态真值，`unreadCount` 只能由当前保留条目的状态派生；单条已读写入必须幂等，禁止用 `unreadCount--` 或“前 N 条”推断真实未读集合。
21. Tracker 巡检可以重复拉取轻量目录用于差分，但只有稳定 ID 未见且位于已读水位线之后的条目才能成为新未读；自动字幕提取等昂贵工作只能发生在这组真正新增未读条目上。
22. 批量目录、预览和导出不得承担 Tracker 的更新发现职责，也不得整体替换 `TrackedSubscription.items`。目录元数据回填必须按稳定条目 ID 合并并保留 `isRead`、`subtitle` 等持久状态。
23. 多 P 条目必须使用稳定页级 ID（包括 p1）；用于平台根查询的 BVID 字段必须保持纯 BV，不得混入 `:pN` 条目后缀。旧 ID 迁移必须保留既有已读与字幕状态。
24. Tracker 主存储 `bse_subscriptions` 只保存标题、稳定 ID、发布时间、已读状态与字幕状态等轻量账本元数据；字幕正文必须按媒体键存入 `UnifiedSubtitleCache`。复制/预览按需取正文，禁止因一次已读写回而重写整批字幕文本。
25. Tracker 的 runtime 通知、storage change、窗口聚焦等重复刷新必须合并为 single-flight/debounce；非 Tracker 页只允许刷新轻量未读摘要，不得无条件重渲染完整追踪列表。
26. 全量订阅巡检必须使用受控小并发而不是串行人工延迟或无界并发；同一轮手动/Alarm 巡检继续共享唯一 in-flight 任务。

## 九、验证边界

Node、Shell 和静态协议测试可在当前工作区执行。Swift/CoreML 编译、XCTest、真实模型 schema/load、真实媒体解码和 Chrome Native Messaging 安装链路必须在 macOS 14+ Apple Silicon 上验证；没有这些证据时不得写成“已实机通过”。

2026-09-10 本机执行接管的可复现验证结果：`node tests/run-tests.mjs` 与 `tests/install-host-tests.sh` 全部通过；standalone `native/SparkSubHost` 的 `swift test` 执行 58 项、0 failure、2 skipped，跳过项仅因 `/tmp/test_speech.wav` 旧模型推理夹具不存在；SparkScribe 的 canonical `build.sh --check` 执行 365 tests / 58 suites 全部通过。打包后的 SparkScribe worker 已用真实短语音完成 Qwen3-ASR timed-cue smoke，bundled helper 的 v2 capabilities/framing、签名、yt-dlp readiness 与真实 Chrome manifest 切换也已验证。当前仓库仍未固定 TypeScript compiler，因此 `tsc -p tsconfig.json` 不能列为可复现 Gate；另外 direct helper/worker smoke 不替代最后的 Chrome 扩展 UI → Native Messaging → SparkScribe → cues 人工 E2E。

## 十、后续扩展方式

- 新增平台时，实现与 `discoverTracks` / `loadTrack` 相同的适配器边界。
- 新增导出格式时，只修改 `core/formatters.js` 与侧边栏选项。
- 迁移批量导出时，使用独立任务模块，不将批量队列写入当前视频状态。
- 新增订阅平台时，在 `core/tracker.js` 中扩充增量比对与 `fetchItemSubtitle` 适配器。
